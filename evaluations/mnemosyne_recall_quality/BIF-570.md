# BIF-570 Mnemosyne selective prefetch regression

BIF-570 adds a gated selective prefetch layer on top of the BIF-568 trusted explicit-recall baseline.

## Gate

Selective prefetch remains **off by default**. It only runs when `$HERMES_HOME/mnemosyne/config.json` contains the literal boolean gate:

```json
{
  "selective_prefetch_enabled": true
}
```

Invalid JSON, non-dict config, non-boolean string gates such as `"true"`, or invalid numeric thresholds fail closed and return no context.

## Safety invariants

- suppressed memories never prefetch
- stale/deprecated/legacy/outdated memories never prefetch by default
- sensitive markers such as secret/token/password/API key/credential never prefetch by default
- memory records must carry explicit eligibility metadata before prefetch can use them:
  - `confidence="high"`
  - `sensitivity="non_sensitive"`
  - `stability in {"stable", "current"}`
  - `current_request_safe=True`
  - traceable `rationale_id`
- empty, trivial, slash-command, irrelevant, sensitive, or risky current-user-intent queries return no prefetch context
- stale/conflicting current facts are handled conservatively by returning no context
- formatted context includes memory IDs, sources, rationale IDs, and eligibility rationale so Biff can explain high-level memory influence
- current user instructions remain authoritative
- the layer is provider-local and does not mutate production `~/.hermes` memory/config in tests; fixtures use pytest `tmp_path` hermes homes
